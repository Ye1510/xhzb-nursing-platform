## 为什么只写了这些

选这几块的共同点是：**响应结构不是单表映射，或者流程跨多个接口**。

- 健康评估：六维数据分表存储，响应体是多个 JSON 段落的组合
- 入住办理：一次申请涉及老人、床位、合同、入住记录四张表
- IoT 设备详情：本地库字段与华为云实时状态合并后返回，字段来源不直观
- 小程序登录：需要走微信 `code2session`，与后台端登录流程不同

其余模块（服务管理、星海智询、报警规则等）均为标准 CRUD，Swagger 生成的文档已经足够，不再重复维护。

> 手写文档与代码存在同步成本，所以只覆盖"读自动文档读不明白"的部分——这是刻意的取舍，不是遗漏。
